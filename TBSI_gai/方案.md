# CUTR-Lite / TBSI 项目说明书

> **2026-07-30 状态更新**
>
> phase-1 oracle 在 LasHeR test 上达到 `56.43 AUC`，相对基线 `55.46` 为 `+0.97`；但冻结 TBSI、仅训练轻量 router 的 ep6 全量结果为 `54.83 AUC`，相对基线 `-0.63`，未达到预设的 `+0.5 AUC` 目标。由此，`CUTR-Lite router-only` 已停止继续调参，本文件以下内容保留为已完成方案与实验设计记录。当前总复盘与后续路线以 [TBSI/EXPERIMENT_REVIEW_ALL.md](TBSI/EXPERIMENT_REVIEW_ALL.md) 为准。

## 1. 项目概述

### 1.1 项目名称

**CUTR-Lite / TBSI：Counterfactual Utility-guided Lightweight Rectification for RGB-T Tracking**

中文名称：**反事实效用引导的 TBSI 轻量融合校正网络**

### 1.2 当前状态

- 基础模型：TBSI（Bridging Search Region Interaction With Template for RGB-T Tracking）。
- 主干网络：双模态 ViT-B，保留原始 TBSI 模板桥接和预测头。
- oracle 上限验证和最小可学习 router 全量验证均已完成。
- 当前裁决：保留 oracle 证据与候选生成基础设施，停止 `router-only`；若继续，转向候选输出级短时序验证，不再扩展同类特征门控。

### 1.3 研究目标

在不重构 TBSI 主干、不破坏原始融合能力的前提下，增加一个轻量、外接、可解释的融合校正器，使模型能够：

1. 判断当前 TBSI 融合结果是否已经足够可靠。
2. 判断当前决策更应保留原始融合、偏向 RGB，还是偏向 TIR。
3. 仅在校正确实有任务收益时修改 TBSI 输出，减少正常样本上的负迁移。
4. 在后续增量版本中，再决定是否引入短期动态作为次级条件信号，而不是一开始把时序分支做成主卖点。

### 1.4 当前证据结论

截至 **2026-07-30**，phase-1 oracle 已得到两条关键证据：

- `mini_lasher_test`：oracle 相对同权重 baseline 提升约 `+1.88 AUC / +2.96 OP75`
- `LasHeR test (244 seq)`：oracle 相对基线注释结果提升约 `+0.97 AUC / +1.65 OP75`
- `LasHeR test (244 seq)` learnable router-only：`54.83 AUC`，相对基线 `-0.63 AUC`

这说明：

- TBSI 输出附近确实存在稳定但不算巨大的可利用校正空间。
- 收益主来源是模态偏置修正，而不是复杂时序补偿。
- 当前低维统计路由器无法学习这部分 oracle gap，oracle 存在不等于效用决策可辨识。
- 下一阶段若继续，应比较候选输出的空间与短时序风险，而不是继续扩大或微调当前路由器。

## 2. 研究背景与核心问题

### 2.1 已有实验揭示的主要矛盾

现有 FCC、可靠性门控和时序令牌实验表现出相似现象：

- 部分困难属性或数据子集获得提升。
- 全量测试中，正常场景或高频属性发生回归。
- 新模块通常能够检测 RGB/TIR 差异，却无法判断这种差异是否真的需要被修正。

RGB 与 TIR 的差异可能来自：

- 低照度、热交叉、噪声、遮挡等模态退化。
- 颜色变化、姿态变化、目标旋转等正常模态特性。
- 目标快速运动、尺度变化等两模态共同动态。
- TBSI 本身已经正确处理的互补信息。

因此，**模态差异不等于模态退化，图像质量也不等于该模态对当前跟踪决策的贡献**。

### 2.2 CUTR-Lite 的核心研究问题

CUTR 不再试图回答：

> 当前 RGB 或 TIR 是否发生了某一种预定义退化？

而是直接回答：

> 如果改变当前融合决策，使其偏向 RGB、偏向 TIR 或短期时序先验，真实跟踪损失会变好还是变坏？

因此，本项目将“模态可靠性”重新定义为：

> **模态证据或时序证据对当前跟踪决策的条件边际效用。**

这一任务定义避免依赖 Gaussian noise、blur、brightness drop 等有限合成退化类型，并使训练目标与最终跟踪指标直接对齐。

## 3. 总体架构

CUTR-Lite 是位于 TBSI 搜索特征融合之后、预测头之前的外部增强模块。

```text
RGB frame ─┐
           ├─> ViT + TBSI ─> F_rgb, F_tir, F_base ─> Router + Rectifier ─> F_out ─> Center Head
TIR frame ─┘                                       │
                                                   │
training GT ─> Counterfactual Utility Evaluator ───┘
                   (training only)
```

其中：

- `F_rgb`：当前 RGB 搜索区域特征。
- `F_tir`：当前 TIR 搜索区域特征。
- `F_base`：原始 TBSI 融合结果。
- `F_out`：经过 CUTR-Lite 选择性校正后的融合结果。

原始 TBSI 路径始终保留，并被视为一个明确的“保持基线”动作。CUTR-Lite 初始输出严格等价于 `F_base`。

### 3.1 当前主线新增模块

当前推进版只新增两个真正需要实现的模块：

1. `Counterfactual Utility Evaluator (training only)`
   对 `keep / rgb / tir` 三个候选动作共用同一个预测头，按真实 tracking loss 生成 soft oracle policy。
2. `Lightweight Utility Router`
   输入当前帧的低维统计和目标中心 pooled feature，输出三路动作权重，用一次残差修正替代多次候选枚举。

当前主线**不新增**独立时序编码器、GRU 状态机、特征重建器或额外 backbone 分支。

## 4. oracle 后的主线方法定义

这份方案的目标不是做一个“大而全”的新框架，而是在 TBSI 外面增加一个**轻量、可回退、可快速验证**的校正器。结合全量 oracle 结果，主线只保留两个角色：

1. `Counterfactual Utility Evaluator`
   仅在训练和 oracle 分析时出现。它比较几个候选动作在 GT 下的真实跟踪损失，生成 soft oracle policy。
2. `Utility Router + Rectification Executor`
   推理时只保留一个轻量路由器和一次校正执行，不重复跑 backbone，不枚举所有动作。

时序先验分支暂时降级为“可选扩展”，只有当三动作主线已经学到稳定增益后，才考虑把它作为附加分支加回去。

### 4.1 动作空间

CUTR-Lite 主线只保留 3 个全局动作：

```text
A0: F_base                         保持原始 TBSI
AR: F_base + eta * D_t             向 RGB 证据偏移
AT: F_base - eta * D_t             向 TIR 证据偏移
```

其中：

```text
D_t = LN(F_rgb) - LN(F_tir)
```

解释原则如下：

- `D_t` 只是当前双模态差分方向，不解释其具体退化原因。
- `A0` 必须显式保留，因为“不改动基线”本身就是一个应被学习的动作。
- `AR/AT` 不是替换 TBSI，而是在 TBSI 输出附近做小幅可回退的偏置修正。

本阶段**不做** token-wise action 扩展，也**不做**时序动作主线训练。若三动作版本已经逼近 oracle 上限，再考虑更复杂动作。

### 4.2 训练期 oracle 效用

对同一次 backbone 输出生成 4 个候选动作，并共用预测头计算各自损失：

```text
loss_k = L_track(Head(F_t(action_k)), y_t)
pi_star_k = softmax(-loss_k / tau)
```

这里的 `pi_star` 是 CUTR-Lite 的核心监督信号。它不回答“哪个模态质量高”，而是直接回答：

> 在当前帧，如果改变融合决策，真实跟踪损失会更好还是更差？

这也是全文最值得讲清楚的唯一核心创新。

### 4.3 推理期轻量路由

路由器输入只保留最必要的信息：

- RGB/TIR 的目标中心 pooled feature
- 当前响应图统计量
- RGB/TIR 差分强度统计量
- 原始 TBSI score map 的峰值、熵、峰谷差等不确定性统计

路由器输出动作分布 `pi_hat_t`，通过蒸馏拟合 `pi_star`：

```text
L_utility = KL(stop_gradient(pi_star) || pi_hat_t)
```

推理时只执行一次期望动作：

```text
a_diff = pi_hat[RGB] * eta - pi_hat[TIR] * eta
F_out  = F_base + a_diff * D_t
```

默认策略是“保守修正”：

- 路由器初始偏向 `A0`
- `a_diff` 零初始化或接近 0
- 对动作幅度设置简单上界

## 5. 论文贡献压缩

不要把 CUTR-Lite 写成 5 个创新点。论文里建议只保留 2 条贡献：

1. 提出一种基于**反事实任务效用**的融合决策学习方式，用 GT 直接构造候选动作的 oracle policy，而不是给模态打抽象“质量标签”。
2. 提出一个**轻量模态路由校正器**，在保留原始 TBSI 的前提下，只在有收益时执行 RGB/TIR 方向的小幅校正，从而抑制全量负迁移。

其余内容的定位建议如下：

- “效用重定义”属于问题视角
- “keep baseline”属于动作设计
- “短期动态可能是附加条件”属于扩展方向，不再属于首稿主贡献
- “低维状态不重建特征”属于实现选择

这样写更适合 EI 或 4 区期刊，也能明显降低 reviewer 对“逐点消融”的要求。

## 6. 训练目标

为控制实现复杂度，首版只保留两个损失：

```text
L_total = L_track + lambda_u * L_utility
```

其中：

```text
L_track = lambda_giou * L_giou
        + lambda_l1 * L_l1
        + lambda_focal * L_focal
```

```text
L_utility = KL(stop_gradient(pi_star) || pi_hat)
```

当前版本建议：

- 不单独引入 `L_dyn`
- 不单独引入 `L_reg`
- 先靠零初始化、动作幅度上界和学习率控制保证训练稳定

只有在三动作版本稳定有效后，才考虑把时序条件作为附加监督或附录分支加回去。

## 7. 训练与推理流程

### 7.1 训练

1. 采样连续两帧 `t-1` 和 `t`。
2. 对 `t` 只运行一次 TBSI backbone，得到 `F_rgb`、`F_tir` 和 `F_base`。
3. 构造 `A0/AR/AT` 三个候选动作。
4. 共用预测头计算 3 个动作的 tracking loss，生成 `pi_star`。
5. 路由器预测 `pi_hat`，用 `L_utility` 做蒸馏。
6. 执行一次期望动作，按正常流程计算 `L_track`。

### 7.2 推理

1. 当前帧正常运行一次 TBSI。
2. 路由器预测动作分布。
3. 执行一次轻量校正。
4. 原始预测头输出目标框和响应图。

推理阶段不运行 CUE，不重复跑 backbone，也不枚举 4 个动作。

---

## 8. 与旧时序令牌方案的区别

旧方案的问题不是“完全错误”，而是它在当前目标下太重，且难以快速验证。CUTR-Lite 的区别可以压缩成三点：

| 旧方案 | CUTR |
|---|---|
| 历史信息直接注入当前高维特征 | 不直接改 backbone，只在 TBSI 输出附近做轻量路由 |
| 默认每帧都增强 | 显式允许保持原始 TBSI |
| 训练信号主要来自 tracking loss 长路径反传 | 额外有 oracle policy 蒸馏监督 |

旧 Temporal Token 可以保留为对比对象，但不再作为主路线继续展开。

## 9. 最小可行性验证

### 9.1 第一阶段：Oracle 上限

先不训练 router，只测动作空间有没有价值。

步骤：

1. 固定 baseline checkpoint。
2. 生成 `A0/AR/AT` 三个主动作的预测结果，并将时序动作仅作为参考上界。
3. 用 GT 逐帧选出损失最低的动作。
4. 统计 oracle AUC、Precision、NormPrecision 及各动作选择比例。

已得到的结论：

- `mini_lasher_test` 的 oracle 增益较明显，说明局部存在可利用空间。
- `LasHeR test` 全量 oracle 仍有 `+0.97 AUC`，说明主线没有被证伪。
- 但全量上限明显低于 mini，因此后续必须走“轻量、保守、快验证”的路线。

### 9.2 第二阶段：Router 恢复率

冻结 backbone，只训练路由器和必要的轻量参数。

重点看三项：

- Router 与 oracle 的动作一致率
- Router decision regret
- 恢复 oracle 增益的比例

继续条件：

- 在 `LasHeR test` 上至少恢复约 `1/2` 的全量 oracle 增益，即约 `+0.5 AUC`
- 正常场景误触发率可控
- `keep` 动作占主导时，整体结果不能回退到基线以下

实际结果：

- ep6 全量 AUC：`54.83`
- 相对基线：`-0.63`
- 相对目标：少 `1.13 AUC`
- 阶段裁决：未通过，停止 `router-only`

### 9.3 第三阶段：全量验证

只做最必要的结果：

- LasHeR 全量
- RGBT234 跨数据集
- 属性级结果
- 参数量、FLOPs、FPS

如果时间紧，随机种子和大规模附加分析可以放到第二版。

### 9.4 当前实施优先级

以下三步为本轮已经执行完毕的历史计划：

1. 实现三动作 oracle 蒸馏训练，不引入新 backbone 分支。
2. 冻结 TBSI，仅训练 router，验证是否能拿到 `+0.5 AUC` 左右的全量提升。
3. 只有当第 2 步成立时，再决定是否恢复时序条件作为附加分支。

第 2 步未通过，因此第 3 步取消。当前不再继续 CUTR router-only 的实现扩展。

## 11. 风险与止损原则

### 11.1 主要风险

1. 动作空间本身只有很小收益上限。
2. oracle 有收益，但轻量 router 学不会。
3. 即使学会，实际增益也不足以覆盖实现和写作成本。

### 11.2 止损原则

- 先看全量 oracle，再决定是否继续实现 learnable version。
- router-only 全量结果已经低于基线，不再通过精简输入或调整动作幅度延长该路线。
- 若 learnable 版本在全量上低于 `+0.3 AUC`，建议停止该主线。
- 在未验证前，不宣称 CUTR-Lite 是“通用插件”或“因果退化识别器”。

当前已触发止损：learnable 版本相对基线为 `-0.63 AUC`。

## 12. 投稿定位与执行节奏

### 12.1 论文定位

CUTR-Lite router-only 当前没有超过基线，不能作为正向方法论文投稿。以下定位仅在后续结构不同的方法取得稳定全量增益后重新评估：

- `EI conference`：ICME、ICIP 一类，中等篇幅，适合讲一个清晰的方法点。
- `SCI 4区 / 较友好期刊`：若想把属性分析、更多消融和跨数据集补齐，可以转更长篇幅。

如果目标是一到两个月内尽快出稿，当前更推荐按**EI 会议风格**组织内容：贡献少、实验硬、叙事短。

### 12.2 建议时间线

原计划及实际状态：

| 阶段 | 状态 | 输出 |
|---|---|---|
| Oracle 上限实验 | 已完成 | mini 与 LasHeR 全量上限 |
| 3-action router 训练 | 已完成，未通过 | 全量 `-0.63 AUC` |
| 跨数据集验证 | 取消 | 未达到 LasHeR 晋级线 |
| 写作与改图 | 暂停 | 当前无正向主结果 |

止损条件已经触发，当前转入总复盘中的分支路线。

### 12.3 一句话方法

以下为已证伪实现的历史方法描述：

> CUTR-Lite 通过训练期反事实动作评估生成 oracle policy，再将其蒸馏为推理期的轻量模态路由器，只在有收益时对 TBSI 融合结果做选择性校正。

### 12.4 证据边界

实验前的核心假设是：

> TBSI 输出附近存在少量稳定有益的校正动作，并且这些动作的效用可以由当前模态证据和少量低维决策统计进行预测。

实验结论将该假设拆为两部分：前半句被 oracle 支持，后半句被 router-only 全量结果否定。

## 13. 代码实现落点

本节记录已经完成的 router-only 实现，不代表当前仍建议继续扩展。

### 13.1 需要新增或改动的核心位置

1. `lib/models/tbsi_track/tbsi_track.py`
   - 在现有 `get_fusion_pack(...)` 和 `forward_head_from_fused(...)` 基础上，新增训练期 `3-action utility distillation` 路径。
   - 增加一个极小 `UtilityRouter`，输入 pooled feature 和 score-map statistics，输出 `pi_hat in R^3`。
   - 默认零初始化，使初始输出近似 `keep`。
2. `lib/train/actors/`
   - 在 tracking actor 中加入 `pi_star` 构造和 `L_utility`。
   - `pi_star` 来自 `A0/AR/AT` 三个候选动作的真实 tracking loss softmax。
3. `experiments/tbsi_track/`
   - 新增一份 `CUTR-Lite` 配置，默认 `freeze backbone + freeze head + train router only`。
   - 学习率单独设置，避免把 baseline 搅动。
4. `tracking/test.py` 与 `lib/test/tracker/tbsi_track.py`
   - 保留现有 oracle 逻辑作为分析模式。
   - 额外加入 learnable router 的普通推理分支，用于和 baseline 直接比较。

### 13.2 Router 最小输入

首版 router 输入严格限制为以下几类，避免再次走向“特征太重、梯度太散”：

- `rgb_roi`: RGB 目标中心 pooled feature
- `tir_roi`: TIR 目标中心 pooled feature
- `base_roi`: TBSI fused target pooled feature
- `diff_stats`: `|rgb_roi - tir_roi|` 的均值、方差、范数
- `score_stats`: score map 的峰值、均值、熵、top1-top2 gap

不把整张 feature map 直接喂给 router，不引入额外 cross-attention。

### 13.3 Router 最小结构

```text
[rgb_roi, tir_roi, base_roi, diff_stats, score_stats]
        -> LayerNorm
        -> Linear(·, 128)
        -> GELU
        -> Linear(128, 3)
        -> softmax
```

设计原则：

- 参数量尽量控制在 `0.2M` 以内
- 不引入 RNN / GRU / Transformer
- 初值偏向 `keep`

### 13.4 训练策略

训练顺序建议固定，不要一开始就端到端：

1. `stage A`: 冻结 backbone 和 head，只训练 router。
2. `stage B`: 若 `stage A` 有稳定增益，再只解冻 `tbsi_fuse_search` 附近的极少量参数。
3. `stage C`: 若仍有效，再决定是否做端到端微调。

### 13.5 成功标准

这条主线的实际工程成功标准很简单：

- 全量 `LasHeR test` 相对 baseline 稳定获得约 `+0.5 AUC`
- FPS 降幅可控
- 不依赖时序支线也能成立

当前未达到第一条，已决定不继续扩成更复杂的 router-only 版本。
