## Gradient and update audit

`CenterPredictor.get_score_map` inserts Strip only after `conv1_ctr`. `cal_bbox` takes `torch.max(score_map).indices` to gather independent size/offset outputs; it does not use `max_score` in box coordinates. The score-only module has no differentiable path from box L1/GIoU through the selected index. Separate real-batch `autograd.grad(..., allow_unused=True)` checks agree:

| State | Focal -> alpha | Focal -> all eight internal conv tensors | L1 -> all nine new tensors | GIoU -> all nine new tensors |
| --- | --- | --- | --- | --- |
| New module, `alpha=0` | nonzero, norm 0.01348 | zero tensors | `None` | `None` |
| Saved epoch-3 candidate, `alpha=-0.013339` | nonzero, norm 0.002321 | all nonzero; e.g. strip-horizontal weight 0.000139, final 1x1 weight 0.002041 | `None` | `None` |

`None` here means no graph path; zero means a connected path multiplied by zero. In three separate diagnostic AdamW updates on the **same reused batch**, step 1 changed only alpha (0 -> +0.000100); all internal gradients and parameter deltas were zero. At step 2 (`alpha` already nonzero), all eight internal gradients and parameter deltas were nonzero. This confirms the expected zero-gate warm-start behavior, not a hidden disconnect. The saved epoch-3 optimizer contains all nine new parameter states, each at step 252 with nonzero first moment. It supports that the real run optimized the branch, though the exact full-run displacement from its unarchived random initialization cannot be reconstructed. The parent M1 267 state tensors remain bitwise equal to the protected checkpoint, as verified in the completed short-run report.

The trained branch's actual feature residual `||refiner(x)-x||/||x||` on the real batch has median **0.00429** (0.429%). On that batch, enabled versus same-weight disabled raw score maps differ by relative L2 0.00175 and maximum absolute 0.00206; neither raw nor Hann-windowed peak changes in 16/16 samples. Thus alpha is not merely a nonzero scalar: the branch changes features and scores, but this batch does not show a changed decision. Residual size alone cannot establish whether further optimization would help.

## Label, grid and tracker readout

- Three synthetic normalized boxes give the exact expected `round(16 * GT center)` heatmap peak and `cal_bbox` center reconstruction (maximum absolute error 0). The real training batch has 16/16 nonempty GT heatmaps, 16/16 rounded centers inside the 16x16 grid and 0 peak-index mismatches. All 48 real fixed-state crops produce nonempty GT heatmaps whose peak matches the same rounding rule; the actual replay crop equals the recorded trace crop.
- The tracker does **not** select from the raw score used by focal training: it multiplies the score map by a centered 16x16 Hann window, then calls `cal_bbox` with that response. In the real training batch, the Hann value at GT label cells has median 0.450; 9/16 are below 0.5. Applying the inference window changes the base raw peak in 3/16 of that batch. On the fixed-state M1 events it changes 0/16 matched-good peaks, 7/16 precursor peaks and 9/16 severe-onset peaks. This is an intentional tracking motion prior in code, **not proven a bug**; it does create a train/inference decision mismatch for any score-only adapter optimized solely against raw heatmaps.
- The sampled search crop origin is integer-rounded, whereas `map_box_back` uses the floating previous-state center minus half the crop side. Decoding with the exact tracker origin reproduces its predicted center within `0.000061 px` on these events; decoding using the integer crop origin can differ by up to `0.478 px`. The subpixel convention needs to be respected when comparing labels, peaks and boxes, but it cannot explain the tens-of-pixels failures by itself. One event's rounded label cell differs from a separate *cell-center-inside-GT* support mask; these are different geometric conventions, not evidence of a mislabeled heatmap.

## Same-state response on M1 events

Candidate `alpha=0` restores M1 float score maps exactly in 48/48 replays. With the trained alpha, all 48 score maps change numerically. Median feature residual is about 0.0043-0.0044 across the three event classes; median maximum absolute raw-score change is 0.00100 (matched good), 0.00193 (precursor), 0.00189 (severe onset). **No raw peak or Hann-windowed peak flips between M1 and Strip in any of the 48 fixed-state frames**, and no resulting box-center change occurs. The windowed GT-support-versus-background margin delta is small: median -0.00061, -0.000059 and +0.000166 for the three classes, respectively. At severe onset, the M1 median windowed margin is -0.02893; the Strip branch's typical score perturbation is too small to overturn many such gaps under this checkpoint, although this does not prove a larger branch would improve tracking.

The M1 windowed peak lies in a GT cell-center support region in 16/16 matched-good, 12/16 precursor and **3/16 severe-onset** frames; Strip has the same counts. The remaining 13 severe-onset frames point to a peak-selection problem under this diagnostic support definition. The three severe frames with a supported peak still have low overlap: `2runfive` has decoded-center error 34.39 px and width/height ratios 2.01/1.58, `bluegirlcoming` 76.91 px and 0.53/0.53, `leftblkboy` 63.73 px and 2.79/2.07. A cell within the GT region does not guarantee a good offset/size readout, especially for large targets; a score-only branch cannot directly repair those regression values. These 16 events are preselected M1 failures, not a population estimate of error proportions.

Other open explanations remain. The focal implementation treats only `target == 1` as positive; neighboring Gaussian cells are down-weighted negatives, and it does not explicitly compare the GT response against the strongest distractor. The causal training sampler draws GT-annotated crops with center/scale jitter, whereas these diagnostic frames use the model's own previous tracking state; their distractor and drift distributions need not match. A 16x16 stride-16 grid can also limit small-target localization independently of the Strip operator. Finally, the earlier current-worktree M1 full-244 replay is not frame-equivalent to the protected archived predictions. None of these points proves an implementation bug or that a particular replacement module would work.

## Decision

**No unexpected code-path break was found in the inspected Strip contract.** The supported diagnosis is **working but weakly decision-active on these difficult fixed states**, with a specific supervision/readout mismatch: only raw heatmap focal reaches the score-only branch, whereas online selection uses a Hann-weighted peak and box L1/GIoU do not train this branch through the discrete peak. The failed proxy result (AUC +0.0045, center improved 1/30) remains unchanged. This does not identify the Strip operator itself as intrinsically unsuitable, and it does not explain LCGA's separate pre-fusion result.

Do not increase alpha, replace kernels or rerun full training from these inspected events. Before another candidate, distinguish the two failure strata on a freshly frozen train-side diagnostic set: (A) wrong windowed peak with readable fused target evidence, (B) supported peak but bad offset/size. If A is common and the target can be decoded from fused features, the one-variable follow-up is to hold the current Strip operator/placement/frozen M1 fixed and test **Hann-aware GT-versus-hard-negative peak ranking** in addition to the existing focal loss, against a newly rerun matched control on an unused dev. If B is common, a score-only loss cannot address it; test a separate shared or regression readout hypothesis instead. An onset margin/peak-distance improvement across sequences is required before any full run. LCGA needs its own loss-path audit if reconsidered; these Strip findings must not be generalized to it.
