# MCCA and Search-Fusion Literature Scout (2026-10-12)

## Question and evidence boundary

Question: can the current MCCA direction be reframed using RGB-T tracking papers that condition fusion on observable search-time evidence?

This is a literature scout, not an experiment or claim of novelty. The external shortlist below was triaged from bibliographic records and arXiv abstracts; only the local TBSI TPAMI paper evidence was checked against the saved full text. Method details and performance claims from the other papers require full-paper/code review before implementation. No training, tracking, code, or protected M1 asset was changed.

## Local M1/MCCA evidence that changes the transfer decision

- M1's failure analysis observes crop-inside center mismatch followed by feedback drift; it does not identify IGF/search fusion as the unique first cause. Current-worktree probe evidence reports that fused search features were not systematically less target-readable than their concatenated pre-fusion inputs, while still remaining weak at severe onsets. See `m1_search_stage_interface_evidence_20261010.md` and `m1_full244_fusion_mechanism_priority_20261010.md`.
- Template MCCA changed messages and passed connectivity/update checks, but ordinary adapters, ranking supervision, and template-feature reliability gating did not produce stable val96 gains. Full-244 G1-G0 was a small positive description with paired intervals crossing zero.
- Moving a MCCA-like adapter after `tbsi_fuse_search` also gave a negative val96 point estimate (AUC -0.6812; PR -0.7675; NPR -0.7787). This does not test IGF: the post-search adapter was not an illumination-conditioned search fusion module and did not directly model candidate confidence, branch response quality, or temporal recovery. The run also had frozen BatchNorm running-state drift, so it is not a clean frozen-state causal test. See `m1_post_search_mcca_frozen_20261012.md`.
- The existing local DBF “IGF replacement” was explicitly not faithful IGF: it did not use the RGB image/GIE illumination path and changed the learned M1 fusion contract. Its negative proxy screen cannot be used as evidence against paper IGF. See `dbf_igf_contract_audit_20261009.md` and `dbf_igf_replacement_short_20261009.md`.

## Assessment

The current MCCA answers: “can a small learned adapter alter cross-modal template MHSA messages and thereby improve later tracking?” It does not directly answer: “which modality/search locations currently support the target over distractors, and how should those search features be fused before CENTER selects and decodes a location?” Rank loss and a template-only reliability gate did not change that input-information gap. The post-search variant changed the insertion position but still lacked an explicit task-relevant reliability or temporal-state signal.

An IGF-inspired direction is scientifically plausible only as a new search-fusion hypothesis, not as a continuation/tuning of current MCCA. The closest defensible formulation is conditional fusion of the existing RGB/TIR search streams before the existing `tbsi_fuse_search`, with the original fusion operator retained. A global illumination scalar is a narrow cue; a broader tracker-specific proposal would need online, deployment-available signals such as per-branch target-versus-distractor response margin, cross-modal response disagreement, and possibly crop/state confidence. These are candidate signals, not yet validated or guaranteed to be trainable/useful in this tracker.

Before creating a module, use an untouched train-side fixed-state cohort to check whether (a) one branch is target-readable while the other favors a hard negative, (b) fusion reduces target-vs-hard-negative margin, and (c) the relevant quality signal can be estimated without GT at inference. Existing probes do not yet establish (a) or (b) consistently, so the current status is **尚未区分 / supports a diagnostic, not a training candidate**. If those patterns do not recur, stop this fusion direction and return to search representation/CENTER readout diagnosis. Any later candidate needs a new experiment ID/config/output and matched parent control; do not alter or overwrite M1.
