# M1 搜索端失效的阶段定位协议（设计稿，未运行）

日期：2026-10-09。Parent：受保护 M1 `TBSI_E_MHSA_FULL_4090D_seed42`，seed 42，epoch 15。问题：在同一目标、同一搜索 crop 和同一 tracker 状态下，目标中心信息是在两路搜索表示形成时已不足，还是经过搜索融合、CENTER 响应或解码后才失去？本稿只定义诊断，不改配置、权重或评测输出，不启动训练、扰动或 GPU 运行。

## 1. 先收紧现有结论

归档 M1 的 377 段持续严重失配中，365 段起点 GT 完整落在**按整数归档框重建的近似** crop 内；这说明初始失配不普遍由搜索范围过小造成，但没有确认这些帧目标清晰可见。后续出界可能维持漂移。当前工作树的 full-244 信息流重放与归档轨迹有 82,219/219,048 帧坐标差超过 2 px，故其响应和梯度不能逐帧解释归档 M1。loc9 的目标注意力富集、非零梯度只排除“该路径完全失活”的简单解释，不证明模板先验被有效转成搜索目标响应。

“搜索特征没有形成稳定、尖锐、模态可靠的响应”仍应拆成三个可检验命题：目标特征**可分性**、CENTER 原始目标**响应**、最终 Hann 解码后的**选择**。特征可分不自动等于响应尖锐，响应尖锐也不自动等于目标峰正确。峰值偏移还可能来自 GT 中心落在离散网格之间、offset/size 误差或窗口先验。不要把所有中心失配直接称为融合错误。

## 2. 真实代码接口与必须拆开的输出

当前模型每模态模板 64、搜索 256 tokens；backbone 输出为 `[RGB template 64, RGB search 256, TIR template 64, TIR search 256]`。`vit_tbsi_care.py` 在指定 ViT blocks 后调用 TBSI；M1 的模板 MHSA 更新模板，再由后续 ViT block 将其影响传给搜索。TBSI 调用点前后 search token 若数值相同，不表示模板无效；要看**后续 block 的搜索输出**。backbone 末端两路 search token 各为 `256×C`；`tbsi_fuse_search` 将按空间排布的两路特征拼接，经已训练的 3×3 Conv-BN-ReLU 映射为 `C×16×16`；M1 legacy 路径把此输出直接交给 CENTER head。

CENTER head 有中心、offset、size 三个分支，原始 `score_map` 是 sigmoid 后的中心响应。实际 tracker 用 `response = output_window * score_map`，取乘窗后的最大格点，再从该格点读取 offset/size、映射回原图并更新状态。因此诊断的最低限度记录是：**原始中心图、乘窗中心图、各自峰值格点、GT 格点、GT 邻域分数、offset、size、最终映射框**。应分别报告峰值格点选择错误、格点正确但 offset 错误、格点/offset 正确但 size 错误；不要仅用 IoU 或最终峰值混合这些机制。

| 标记 | 精确采集位置 | 可回答的问题 |
|---|---|---|
| S0 | 最后一次模板 MHSA 前后模板；后续 ViT block 的 RGB/TIR search 输出 | 模板信息何时进入搜索；TBSI 调用处 search token 原样传递不能误判为无效。 |
| S1 | backbone 最终 `norm` 后两路 search token，reshape 为 `C×16×16` | 融合前两模态各自有无可读的目标线索。 |
| S2 | `tbsi_fuse_search` 输出，即 CENTER head 输入 | 融合后信息是否仍可由同等容量探针读出。S2 与“head 前”在 M1 legacy 路径是**同一张量**，不重复列为独立阶段。 |
| S3 | CENTER head 中心分支的原始 `score_map`，及独立的 offset/size 图 | head 是否把输入映射到正确目标格点；尺度/偏移误差是否独立存在。 |
| S4 | Hann 乘窗后的 response、argmax 格点、最终框和下一状态 | 解码先验或状态反馈是否把已正确的原始响应改坏。 |

原始 S1/S2 特征没有“天然的响应图”。不能直接比较其范数、余弦值或 entropy 并断言融合前后目标判别能力升降。应先做**同一协议、同一容量、仅 train-fit/dev-evaluate** 的轻量读出探针，或使用下述冻结 M1 输出端的受控接口干预。探针衡量信息可读性，不是模型实际使用了该信息的证明。

## 3. 取样、分层与冻结条件

只用 LasHeR **train/dev**；在读取任何新增诊断数值前冻结成员、事件算法、随机种子和 SHA256。以**序列**划分 probe-fit 与 dev，不能把同一序列相邻帧分入两侧。建议从已有三条 train trace 核验采样/采集可行性，再在预先固定的 train-side 候选序列中按统一规则取每条最多一个首个持续严重失配起点、一个前驱窗口、一个在 crop 内的正常窗口；数量以资源预检决定，上限建议约 16–24 条序列。正常/失败必须匹配目标尺寸分位、相对运动、crop 归一化中心位置和可见性；匹配不成则标为未配对，不强行对照。

事件入组条件：GT 宽高有效；起点前一帧到当前帧状态可重放；目标至少大部分位于**实际 tracker crop**，而不是仅归档近似 crop；候选严重失配为 IoU<0.2 且连续至少 30 帧；人工复核目标在 RGB、TIR 至少一路可辨。人工标注盲于该帧各阶段指标，记录完整可见/部分遮挡/不可辨、RGB/TIR 各自的可辨性、明显错位与相似干扰，并保留带 GT/预测框的图、标注规则和双人不一致项。完全遮挡、无效 GT、crop-out 单列，不混入“目标可见但选错中心”。

同一事件使用**归档/重放对应的前一 tracker 状态、模板、动态模板、crop、resize factor、图像与窗口**固定单步输入，所有诊断臂只改变声明的一个接口。先逐框比较重放与其 parent trace，再提取内部特征。当前源码若不能与归档 M1 做预测 parity，本诊断只解释“当前源码 + 固定 M1 权重”的**独立 replay parent**，不得沿用归档 M1 的事件框作一一对应结论；可改用当前 replay 的 train-side 闭环事件，保存新身份、配置和完整源码快照。不能为了匹配结果临时挑掉失败序列。

## 4. 有限诊断切片和判别指标

### P0：身份与数值闸门

校验 config/checkpoint 哈希、代码快照、train/dev manifest、序列和帧、FP32/eval、tracker 参数、输出窗口、crop-to-image 坐标变换。重前向相对**同一次 trace**保持逐框容差 `0.01 px`；归档 parity 单独报告逐序列/逐框差异，不用同次 trace parity 冒充归档复现。任何采样坐标对齐错误、模态顺序错误、GT 在实际 crop 外或明显图像/标注错位，先修正协议或排除并留痕。若 P0 未通过，后续切片不做模块归因。

### P1：冻结观测和解码分解，先于任何训练

对失败起点、前驱与匹配正常帧捕获 S0–S4。GT 框投影到 16×16 grid；前景 mask 用 GT 覆盖权重构造，边界留缓冲区，背景 mask 排除目标附近与无效像素。S3/S4 分别统计 GT 邻域分数/最大背景分数的 margin、GT 格点 rank、目标质量占比、峰值距 GT 中心的**像素和 GT 尺度归一化距离**、归一化空间熵、top-2 峰值差。再记录原始图 argmax、乘窗 argmax、两者框误差、GT 附近 offset/size 误差和实际选中格点的 offset/size 误差。峰值幅度、熵应在同尺度同输出定义内比较，不能把原始 score 和乘窗 score 当同分布。

S1/S2 的目标判别力使用两层证据：先比较目标与**同一帧难背景**的 whitened cosine/马氏距离及 RGB/TIR 局部一致性；再用仅在 fit 序列学习的共享容量 `1×1` 线性读出器（S1 RGB、S1 TIR、S1 concat、S2 分别一臂，输入按 fit 集单独标准化），在完全隔离的 dev 序列计算 GT-grid AP/target-vs-background margin 和峰值位置。特征维度不同，探针参数量需匹配或用预先固定的投影维度；报告 fit/dev gap。探针好只能说明信息在该张量**可解码**，不能证明原 head 本应读出，也不能把 S1 与 S2 读出差称为已证实的融合因果效应。

### P2：固定状态的最小接口反事实

在同一帧、同一 crop、同一冻结权重的 M1 上，每次只改变一个输入端或一个接口，并保留相同幅度、相同空间面积的非目标位置控制。先做轻度单模态目标邻域模糊/遮挡、TIR 噪声或 1-token 局部错位；记录扰动前后 S1 两路、S2、S3/S4 的**同样指标**和另一未扰动模态的变化。不要在当前预测中心裁剪扰动，因为失败帧会偏向错误位置；用 GT 仅作离线诊断定位，推理算法不得访问 GT。对扰动做至少两级幅度并检查输入分布漂移；极端遮挡只作压力上界，不能当自然场景结论。

进一步的接口对照可在固定 S1 时独立送入原 `tbsi_fuse_search` 与受控输入变体，例如单模态局部替换为同帧邻域背景值、两路互换的负对照；保持 head 和窗口固定，量化 S2、原始 S3 与最终 S4 的变化。**单模态输入屏蔽是分布外干预**，只有方向在多个序列、温和幅度与非目标控制下稳定，才支持“此输入会影响坏峰”；不能由一次改善推断该模态天然不可靠或训练门控必然有效。禁止直接把未经训练的 mean/concat 输出送入旧 head 后用其 IoU 判定新 fusion 优劣，因 head 输入分布已变。

### P3：仅在 P1/P2 仍无法区分时考虑校准臂

用户提出的 D1（冻结 backbone 和 fusion，只训 CENTER head）是**受限容量试验**：若独立 train-fit 后 dev 恢复，说明 S2 含可利用信息且原 head/训练映射可改进；不能单独断言原 head 是首因，因为重新训练同时改变监督、优化和表示读取方式。与“只校准中心分支”和“中心/offset/size 全部校准”分开，保持相同训练步数、样本、增强、LR 调度及独立配置/输出。先看 P1 中原始响应、Hann、offset/size 分解是否已足够，无必要不启动。

用户提出的 D2（替换 `tbsi_fuse_search`）属于**候选方法实验**，不是纯诊断。若需要证明接口容量限制，先采用同一 S1 输入、同一 CENTER head 训练协议的成对 fusion/head 联合校准与 legacy 对照，明确训练预算和 head 适配的混杂；或保留原融合输出加零初始化残差 `F_out = F_M1 + alpha * deltaF` 做单变量候选。新 1×1/3×3/局部增强结构同时改变容量、感受野、参数初始化与优化，不能混在一轮里归因。D1/D2 只有在 P1/P2 给出明确分支方向后再单独立项，不以本次 test-set 分桶筛选。

## 5. 预先定义的决策矩阵

| train/dev 上的稳定观察 | 最窄解释 | 下一步及反证 |
|---|---|---|
| S1 两路及 concat 探针均差，S2 也差；S3 无正确目标峰 | 搜索表示或其上游模板到搜索传递不足 | 先检查实际 crop、目标可见性、尺度与 S0→S1；若同 crop 的早/晚搜索特征有目标可读信息则该解释被削弱。 |
| S1 至少一路目标可读、S2 探针和 S3 都差；轻度污染在目标位置显著放大且非目标控制无此效应 | 搜索融合接口或局部模态可靠性值得进一步区分 | 只提出一个接口级残差/可靠性假设；若 S2 探针仍好而仅 S3 差，应转查 head。 |
| S1 与 S2 探针均好，S3 原始中心图目标 rank/margin 低 | 原 CENTER 中心映射可能未读出已有信息 | 先做中心分支受限校准；若 dev 无恢复，弱化该解释。 |
| S3 原始目标峰正确，S4 乘 Hann 后选到别处 | 窗口/解码先验失配 | 固定模型检验窗口强度和目标位移；不应训练局部模块来解释窗口问题。 |
| S3/S4 峰格点接近 GT，但最终中心/IoU 差 | offset、size 或 crop-to-image/clip 误差 | 分别核查 offset/size 的 GT 格点与选中格点，及 resize/map-back；中心图不是主要瓶颈。 |
| 只有小目标/高运动恶化，但模态局部差异及温和污染响应不分组 | 空间分辨率或状态/位移优先 | 先排查离散网格与 crop 状态；局部模块只是候选解释，需单变量验证。 |

“S1 好、S2 差”本身是探针关联，不等同 `tbsi_fuse_search` 因果破坏；须结合固定状态干预、非目标控制和可重复的 S3/S4 变化。“D1 改善”或“D2 改善”是再训练后的方法潜力，也不等同原故障的唯一根因。允许同时存在多个瓶颈，按最早出现且可被最小干预影响的接口优先，不强制单标签结论。

## 6. 统计、停止条件与资源边界

主要单位为**独立序列/独立事件**，不把相邻帧当独立重复。每条序列先汇总事件起点与匹配窗口的配对差，再报告序列中位数、方向一致的序列数和按序列 bootstrap 区间；同时公开每序列散点/表格、失败和无效项。预先锁定主指标为 GT-grid rank/margin、峰值距离、原始/乘窗 argmax 翻转、中心与 offset/size 误差；其他多指标探索单列，不以单个 p 值选择模块。至少给出小目标、高运动、相似外观、热交叉、低照度的分层描述，但样本少时只报告成员和值，不宣称稳定性或因果。

计算边界：现有空余磁盘约 5.1 GiB，仅保存帧级标量、少量带框核查图和必要的单帧张量；完整 `C×16×16` 多层全帧特征不落盘。优先复用已有三序列 train trace、逐步计时后再扩大；诊断运行按仓库全局上限核算资源密集进程，最多 2 个实际进程，训练主进程加 worker 另按顶层规则。若采样/重放无法建立可靠 parent parity、人工可见性不足，或两轮有限切片仍不能改变接口判断，则停止扩大切片，记录“不可识别”并返回 provenance/数据问题；不靠增加测试集分桶或更多 attention map 补结论。

本设计不产生新性能指标，因此当前不新增实验运行登记。实际启动任何 P0–P3 后，须记录独立 ID、manifest、代码快照、配置和 checkpoint 哈希、环境、完整命令、GPU 时长、失败/中断状态及证据路径，并同步更新实验资产 Markdown 主表与 CSV。受保护 M1 config/checkpoint/归档结果保持只读。
